Step 3: Create the Ansible Playbook
Create a file named webapp.yml using the Nano text editor.
nano webapp.yml
The Nano editor will open. Enter the following complete playbook.

---
- name: Deploy a Simple Web Application
  hosts: localhost
  connection: local
  become: true

  tasks:
    - name: Install Apache web server
      ansible.builtin.apt:
        name: apache2
        state: present
        update_cache: true

    - name: Start and enable Apache
      ansible.builtin.service:
        name: apache2
        state: started
        enabled: true

    - name: Deploy the web application
      ansible.builtin.copy:
        dest: /var/www/html/index.html
        content: |
          <!DOCTYPE html>
          <html>
          <head>
            <title>My Ansible Web App</title>
          </head>
          <body>
            <h1>Hello from Ansible!</h1>
            <p>My web application was deployed automatically.</p>
          </body>
          </html>
        mode: "0644"

    - name: Verify the web application
      ansible.builtin.uri:
        url: http://127.0.0.1/
        status_code: 200
      register: web_result

    - name: Display deployment status
      ansible.builtin.debug:
        msg: "Web application deployed successfully!"
Explanation of the playbook:
Instruction
Purpose
hosts: localhost
Runs the playbook on the local Ubuntu system.
connection: local
Uses a local connection instead of SSH.
become: true
Executes tasks with administrator privileges.
apt
Installs the Apache web server.
state: present
Ensures Apache is installed.
service
Starts Apache and enables it at boot.
copy
Creates the HTML file in Apache's web directory.
uri
Sends an HTTP request to verify the webpage.
debug
Displays the successful deployment message.

cd /etc/ansible

tree -L 3

/etc/ansible/
├── hosts

Step 12: Check the playbook syntax
Before execution, validate the YAML syntax:
sudo ansible-playbook stack.yml --syntax-check
Expected output:
playbook: stack.yml
If an error appears, check the indentation in the YAML files. YAML requires spaces, not tabs.
Step 13: Execute the Ansible playbook
Run the playbook:
sudo ansible-playbook stack.yml
Ansible will execute the tasks in this order:
Gather system facts.
Install Git.
Install PostgreSQL.
Start PostgreSQL.
Install Apache.
Start Apache.
Expected output will contain tasks similar to:
PLAY [Configure the complete software stack]

TASK [Gathering Facts]
ok: [localhost]

TASK [prerequisites : Install Git]
changed: [localhost]

TASK [postgresql : Install PostgreSQL]
changed: [localhost]

TASK [postgresql : Start PostgreSQL service]
changed: [localhost]

TASK [apache : Install Apache web server]
changed: [localhost]

TASK [apache : Start Apache service]
changed: [localhost]

PLAY RECAP
localhost : ok=6  changed=5  unreachable=0  failed=0
The exact number of changed tasks may vary if the packages are already installed.
Successful execution: The playbook should finish with failed=0.
Step 14: Verify Git installation
Execute:
git --version
Expected output:
git version 2.x.x
The exact version depends on the Ubuntu package repository.
Step 15: Verify PostgreSQL installation and service
Check the PostgreSQL version:
psql --version
Check the service:

Expected status:
Active: active (running)
Press q to exit the status screen.
Step 16: Verify Apache installation and service
Check the Apache version:
apache2 -v
Check the service:
sudo systemctl status apache2
Expected status:
Active: active (running)
Step 17: Verify the Apache webpage
Open a web browser and enter:
http://localhost
The default Apache welcome page should appear.
You can also verify it using the terminal:
curl -I http://localhost
Expected response:
HTTP/1.1 200 OK
This confirms that Apache is serving web requests successfully.
Step 18: Verify idempotency (optional but useful)
Run the playbook again:
sudo ansible-playbook stack.yml
If everything is already installed and running, most tasks should report:
ok: [localhost]
This demonstrates idempotency: Ansible maintains the desired system state without unnecessarily reinstalling or changing components.
